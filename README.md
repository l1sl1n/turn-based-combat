# Задача 17: Пошаговый бой (юниты, эффекты, способности)

Данный проект представляет собой библиотеку классов и консольное приложение, симулирующее пошаговый бой между двумя командами юнитов. Проект выполнен в рамках 1-й аттестации по дисциплине «Объектно-ориентированное программирование».

## 🛠 Технологии
*   **Java 21**
*   **Maven** (сборка проекта)
*   **JUnit 5** (автотесты)

## 📖 Описание модели предметной области
Проект построен с использованием принципов ООП и современных возможностей Java 21.

### 1. Юниты (Иерархия `sealed`)
Базовый класс `Unit` является закрытым (`sealed`), что гарантирует наличие только четырех архетипов бойцов:
*   `MeleeFighter` — воин ближнего боя (много здоровья, высокая защита).
*   `RangedFighter` — стрелок (высокая инициатива, средний урон).
*   `Mage` — маг (наносит огромный магический урон, но очень хрупкий).
*   `Healer` — лекарь (может лечить союзников).

У каждого юнита есть здоровье, инициатива (определяет порядок ходов), базовая атака, защита и сопротивляемость магии.

### 2. Способности (Интерфейс `Ability`)
Каждый юнит умеет применять способность. Способности реализованы через интерфейс, что позволяет легко добавлять новые:
*   `MeleeStrikeAbility` (физический удар)
*   `FireballAbility` (огненный шар)
*   `PoisonBoltAbility` (снаряд с ядом)
*   `HealAbility` (лечение)
*   `ShieldSelfAbility` (наложение щита)

### 3. Эффекты (Иерархия `sealed` и `enum` правила сложения)
Эффекты накладываются на юнитов на определенное количество ходов. Для них реализована иерархия:
*   `PoisonEffect` (яд, наносит урон в начале хода)
*   `ShieldEffect` (поглощает входящий урон)
*   `StunEffect` (оглушение, заставляет пропустить ход)
*   `BuffEffect` (увеличивает атаку)

**Повышенный уровень:** Реализовано правило сложения эффектов (`StackingPolicy`). При повторном наложении эффекта программа смотрит на его политику (например, яды складываются по силе — `STACK_POWER`, а оглушение просто обновляется — `REFRESH`).

### 4. Типы урона (`enum` с полями)
Перечисление `DamageType` хранит в себе таблицу уязвимостей. Например, если ударить мага огнем (`FIRE`), его уязвимость умножит урон на 1.5. А если ударить его святой магией (`HOLY`), то урон снизится в два раза (сопротивление).

### 5. Движок боя и Журнал
*   `CombatEngine` — управляет циклом боя. Сортирует юнитов по инициативе, вызывает тикание эффектов, проверяет оглушения и заставляет юнитов атаковать.
*   `CombatLog` — записывает каждое событие (кто кого ударил, сколько урона прошло, кто умер).
*   `CombatDecision` — запоминает каждое решение (кто, какую способность, на кого применил). Благодаря этому реализован **повышенный уровень: воспроизведение боя (`replay`)** — бой можно проиграть заново с теми же решениями, и результат будет идентичным.

### 6. Исключения
Для предотвращения некорректных действий используется собственное проверяемое исключение `DeadUnitException` (например, при попытке атаковать или лечить мертвого юнита). Исключение перехватывается в демонстрации и выводит понятное сообщение в консоль.

### 7. Инкапсуляция и equals/hashCode
*   Все поля классов закрыты (`private`).
*   Списки эффектов и журнал событий возвращаются наружу только в виде неизменяемых копий (`List.copyOf`), чтобы их нельзя было изменить извне.
*   Классы событий и решений реализованы как `record` (Java 21), что автоматически гарантирует корректную работу `equals` и `hashCode`.

## 🚀 Как запустить

### Способ 1: Через IntelliJ IDEA (самый простой)
1. Откройте проект в IntelliJ IDEA.
2. В левом меню найдите файл `src/main/java/com/combat/demo/Demo.java`.
3. Нажмите на зеленую стрелочку `▶` слева от метода `public static void main` и выберите **Run 'Demo.main()'**.
4. Результат боя отобразится в нижней панели **Run**.

### Способ 2: Через терминал (Maven)
В корневой папке проекта (где находится файл `pom.xml`) выполните команду:
```bash
mvn compile exec:java -Dexec.mainClass="com.combat.demo.Demo"
